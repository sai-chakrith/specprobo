# Validation record and acceptance boundaries

Validation date: 2026-10-08 (local date). Development runtime: Python 3.14 on Windows; dependency lock supports Python 3.11+. Independently installed diagnostic parser: udsoncan 1.26.1. Actual ECU, local learned-model and Docker runtime validation were unavailable. The supplied Automotive Engineering case-study PDF, Case Study 5, was used as the requirements reference.

## Reproduced defects and regression evidence

The first correctness regression file failed all ten checks before correction: boolean/numeric/string `!=` negatives, simultaneous numeric bounds on one signal, prose DID/routine binding and decimal handling, hidden setup/intermediate response failures, and timeout classification. Eight specification checks also failed before validation fixes. Further failing tests reproduced NRC priority divergence, boolean/numeric coercion, operation scope, nested unknown-field loss, typed prose deduplication, disabled DID permissions, invented normalized-JSON source rows, suppression-bit handling, data words mistaken for spreadsheet headers, ambiguous case-insensitive names, schema defaults cited as source facts and concurrent audit ID collisions.

Implemented protections:

- Parsed prose is retained and attached to the correct identifier kind. Merged clauses retain every contributing source reference. Read conditions use `read_preconditions`; write conditions use `preconditions`. Empty DID direction permissions disable the operation. Same-number DID/routine targets remain separate. Unparsed conditional prose is explicitly unresolved.
- Positive witnesses satisfy every typed conjunct. Independent negative witnesses violate one conjunct while preserving the others where feasible. Redundant predicates without an independent witness remain a review consideration; arbitrary OR is unsupported.
- Generated snapshots store expected responses for every setup and intermediate request. Execution stops at the first failure and retains phase, request, expected, actual and classification. Missing frames/timeouts are communication failures; legitimate wrong ECU responses are mismatches; setup failures are identified separately. Cases lacking complete setup/intermediate expectations fail configuration checks before communication. Generation rejects setup flows that cannot establish the requested state. Negative-test requests belong in diagnostic steps, not setup. Application revision gates prevent old generated snapshots from executing.
- Nested unknown fields are forbidden; references, supported service models, parameter lengths, masks, units, contradictions and unresolved information block generation. Complete NRC ordering is mandatory for the supported rules. The synthetic OEM-B priority typo (`0x21` in place of modeled `0x33`) was corrected explicitly; no external OEM document was changed.
- Header aliases and title/repeated-header handling preserve page/table/sheet/row locations. Conflicting aliases and source values are rejected. Normalized JSON evidence has unknown raw line numbers and explicit origin/defaulted flags; those flags survive into suite provenance. Schema-only defaults are excluded from indexed source evidence; legacy normalized JSON must be reingested because its original/default distinction cannot be recovered. Scanned pages and ambiguous tables require OCR/engineer correction. The synthetic S3 header was corrected from seconds to milliseconds; actual seconds columns are converted explicitly.

Run `uv run pytest -q --junitxml=docs/evidence/pytest.xml`. The captured [pytest output](evidence/pytest.txt) and [JUnit record](evidence/pytest.xml) are the authoritative latest counts. [Lint](evidence/lint.txt) and [strict type checking](evidence/types.txt) record static checks. The final local run reports **102 passing tests**, with 150 dependency deprecation warnings retained in the output. [Live HTTP smoke evidence](evidence/live-smoke.json) records healthy startup, a valid audit chain, simulator default, individual authentication mode and HTTP 403 for uncontrolled workspace creation. Tests include source/field/suite approval and revocation, snapshots, workspace isolation, runnable Python export, persistent retrieval, failure recovery and UI smoke coverage.

## Independent protocol and timing checks

Hand-authored golden bytes are in `tests/golden_vectors.py`; additional configured-data, seed/key, write-read-state and threshold vectors are in `tests/test_configured_protocol.py`. Neither implementation computes those expected bytes. Oracle and simulator implementations are separate, but share the specification and therefore may share conceptual errors.

`tests/test_protocol_independent.py` decodes session responses through udsoncan. This exposed the missing P2/P2-star fields for the declared 2020 wire format: session `0x03` now produces `50 03 00 32 01 F4` (50 ms and 5000 ms). `tests/test_independent_outcomes.py` independently parses and checks reset/security/routine/write/tester-present response fields. Decoding is **structural interoperability evidence**, not an independent evaluation of ECU semantics, NRC selection, seed/key validity or complete ISO compliance.

P2/P2-star, response-pending, missing/malformed/uncorrelated responses and response masks are tested using scripted message adapters. S3 uses virtual time at S3−1, S3 and S3+1; a simulator deliberately missing expiry is detected. Adapter-reported elapsed times must be validated against a monotonic clock on the actual transport. No physical CAN/ISO-TP timing was measured. Positive-response suppression respects the configured support flag, decodes the low seven subfunction bits and preserves state effects/negative replies. The disabled-flag model sends an unsuppressed response; OEM-specific unsupported-bit policies remain a bench validation dependency. Silence alone cannot prove ECU receipt; approved bench suppression cases need follow-up liveness/state probes. A simple caller-provided approval reference is not a cryptographic bench authorization system; the API exposes simulator execution only.

## Extraction, retrieval and model evidence

[Demo extraction results](evidence/synthetic-extraction.txt) exercise the original two synthetic fixtures; perfect scores there do not estimate OEM extraction reliability. The frozen candidate manifest and separate documents are in `data/evaluation/`. [Candidate results](evidence/candidate-extraction.json) explicitly retain the failed PDF and per-field missed requirements. The XLSX routine fields succeed; the gridless PDF produces an unresolved-target error and seven missed field requirements. Correction action counts are reported; measured correction seconds remain null. This tiny synthetic set has **not been independently engineer-reviewed** and is not an accepted OEM holdout. Do not tune on it and then reuse its scores as independent evidence.

The local AI evaluation requires both a configured learned embedding model and an available local model. [Current result](evidence/local-ai.json): `NOT_RUN`. Unit/API tests use controlled outputs and establish guard behavior only. Answer support is an exact extractive-span gate, not semantic entailment. Structured conflict detection is bounded to recognized paths and may abstain across different ECU documents. Similarity and extraction confidence fields are not calibrated correctness probabilities.

## Recovery, access and deployment evidence

SQLite file-backed audit writers are serialized before selecting the previous hash; 30 events from six concurrent writers preserve the chain. A database lock forces rollback; retry succeeds without a broken chain. Indexing interruption preserves the document, raw upload and durable job; restart/retry upserts the same vector IDs. A failure on the second batch review leaves zero committed decisions. Backup restoration verifies SQLite integrity and the audit chain. Older schema versions upgrade by additive table creation; future versions are rejected. This does not prove durability under every filesystem/power-loss scenario. A hash chain does not protect against an administrator rewriting the database and its trust root.

Individual mode tests cover missing credentials, workspace membership, viewer/reviewer separation and membership revocation. Shared-key compatibility mode remains an explicit weaker localhost option. Enterprise identity integration, token expiration policy, TLS, rate limits, penetration/load tests and Windows/Linux secret-file permissions require deployment acceptance. Docker definitions were inspected and use the dependency lock, but Docker is not installed on this host: runtime acceptance is pending.

## External acceptance dependencies and reproducible procedures

1. **OEM documents and independent reviewers:** obtain authorized customer PDF/XLSX samples across layouts, scanned pages and conflicting revisions. Split by document family/ECU before development. Have two diagnostic engineers annotate every field/condition, operation scope, identifier, unit and source location; adjudicate disagreements. Freeze files and hashes, record reviewer identities and measured correction time by field type. Supply a manifest to `python -m eval.heldout_eval --manifest <manifest.json> --output <report.json>`. Report false positives, false negatives, missed safety-relevant requirements and layout rejection rate; acceptance thresholds must be signed before the run.
2. **Approved ECU bench and reference diagnostic stack:** supply ECU firmware/version, VIN or anonymized ECU identity, variant coding, authorized service catalogue/NRC order, data/seed fixtures, proprietary key provider, ISO-TP/CAN settings and reviewer-approved safe operations. Independently write expected request/response/timing vectors. Replay the same suite through the reference implementation and a reviewed `MessageAdapter`; preserve raw frames and monotonic timestamps. Test P2 boundaries, pending under P2-star, pending exhaustion, dropped/malformed frames, S3 session/security expiry and tester-present activity. Investigate each mismatch; never copy oracle output into the bench ground truth.
3. **Local model infrastructure:** supply an installed Ollama model/tag and artifact digest, reachable local endpoint, approved embedding directory/digest and local-model dependencies. Run `python -m eval.local_ai_eval --output <report.json>`. Review each saved claim/citation pair for entailment, correctness and omission; assess abstention on missing/contradictory evidence and injected instructions. Report retrieval recall/MRR separately from human answer-groundedness, model latency and failure rate. The built-in corpus is synthetic; an engineer-reviewed OEM QA corpus is still needed.
4. **Deployment:** supply Docker executable/daemon and authorized image/package registry access. Follow `OPERATIONS.md`; test Python 3.11 container startup, authentication, health, upload/recovery/review/export/run, restart, backup restoration and non-root persistent-volume permissions. Record exact image digest and results. The local Windows Python 3.14 run is not a substitute.
5. **Supervised engineering pilot:** supply participants, authorized requirements and a safe reference bench. Execute `PILOT.md`. Until observations and independent defect confirmations exist, authoring-time improvement, review-effort reduction, acceptance rates and confirmed ECU defects are unmeasured.

## Remaining limitations

Gridless/arbitrary PDF layouts, OCR, operation-ambiguous prose, disjunctive conditions, proprietary seed/key functions and variable seed sizes, full UDS service/state-machine coverage, real reset/data persistence, CAN/ISO-TP, and CAPL/CANoe/ODX/CDD integrations remain unsupported or externally unvalidated. Python export is the implemented automation framework. Coverage counts describe generated model cases; they are not full-standard requirement coverage. Simulator mutation outputs in [the mechanical report](evidence/simulator-mutation.txt) describe finite injected changes, and survivor classifications are candidate equivalence over finite sequences rather than proofs.

Readiness against Case Study 5: the reviewable assistant workflow and bounded automated test pipeline are implemented and locally checked. Independent OEM extraction quality, ECU behavior/timing, learned-model answer quality, deployed operation and demonstrated engineering benefits are **not yet accepted**. Use only a supervised simulator pilot until the applicable external gates have been completed.
